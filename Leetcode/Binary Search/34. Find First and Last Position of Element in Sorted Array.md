## 📖 Problem Statement

Given a sorted array `nums`, find the **starting and ending position** of a given `target` value.

If the target is not found, return:

[-1, -1]

The solution must have:
```text
O(log n)

runtime complexity.
```
---

# 💡 Observation

Since the array is sorted, we can use Binary Search to find the target.

However, finding the target once is not enough because the target may occur multiple times.

For example:
```

nums = [5, 7, 7, 8, 8, 10]
                 ↑
               target
```

For target 8:

First occurrence → index 3
Last occurrence  → index 4
# 🧠 Approach 1 : Binary Search + Linear Expansion

First, perform a normal Binary Search.

### If the target is found at mid:

Move left from mid to find the first occurrence.
Move right from mid to find the last occurrence.

#### 🔍 Finding the First Occurrence

Start from the found position:

``` java
int l = mid;

// Move left while the value is equal to the target:

while(l >= 0 && nums[l] == target){
    l--;
}
```

When the loop stops, l is one position before the first occurrence.

Therefore:
```
arr[0] = l + 1;
```
#### 🔍 Finding the Last Occurrence

Similarly, start from mid and move right:
``` java
int r = mid;

while(r < n && nums[r] == target)
    r++;
```
When the loop stops, r is one position after the last occurrence.

Therefore:
```
arr[1] = r - 1;
```

---

💻 Code
``` java
class Solution {

    public int[] searchRange(int[] nums, int target) {

        int left=0;
        int right=nums.length-1;
        int n=nums.length;

        int[] arr={-1,-1};

        while(left<=right){

            int mid=left+(right-left)/2;

            if(nums[mid]==target){

                int l=mid;

                // go left and check if its the first occurence
                while(l>=0 && nums[l]==target){
                    l--;
                }

                arr[0]=l+1;

                // go right to find the last occurence
                int r=mid;

                while(r<n && nums[r]==target)
                    r++;

                arr[1]=r-1;

                break;

            }else if(nums[mid]>target){

                right=mid-1;

            }else {

                left=mid+1;
            }
        }

        return arr;
    }
}
```

---

## ⚠️ Problem With This Approach

Although Binary Search is used to find the target, the search for the first and last occurrence is done using linear traversal.

Consider:
```
nums = [8,8,8,8,8,8,8,8,8,8,...]
```
If the target occurs many times, the left and right loops may traverse a large portion of the array.

Therefore, the complexity can become:

```
O(log n) + O(n)
```

which simplifies to:

```
O(n)
```

But the problem specifically requires:

```
O(log n)
```

---

## 🚀 Optimization

The first and last occurrences should also be found using Binary Search.

Instead of:
```
Binary Search
      ↓
 Find target
      ↓
Linear Search
   ↙       ↘
First     Last
```
we need:

Binary Search → First Occurrence

Binary Search → Last Occurrence

So we perform two Binary Searches:

```Binary Search 1```

Find the first index where:

```
nums[index] == target
```

```Binary Search 2```

Find the last index where:

```
nums[index] == target
```

Each Binary Search takes:

```O(log n)```

Therefore:
```
O(log n) + O(log n) = O(log n)
```

# 🎯 Key Takeaways

- Binary Search can quickly find a target in a sorted array.
- Finding one occurrence is not enough when duplicates exist.
- Linear expansion can make the solution O(n).
- To satisfy the required O(log n) complexity, both boundaries should be found using Binary Search.
First occurrence → Lower Bound idea.
Last occurrence → Upper Bound - 1.
This problem is a good application of the Lower Bound and Upper Bound concepts.
