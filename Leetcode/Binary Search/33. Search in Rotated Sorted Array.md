## 📖 Problem Statement

Given an ascending sorted array that has been **rotated** at an unknown index, find the index of a given `target`.

All elements are **distinct**.

The solution must run in:

```text
O(log n)
```

---

## 💡 Observation

Even though the entire array is no longer sorted, **at least one half of the array is always sorted**.

For every iteration:

```text
left ---- mid ---- right
```

Either:

```text
left → mid
```

is sorted,

or:

```text
mid → right
```

is sorted.

We identify the sorted half and check whether the target can lie inside it.

---

# 🧠 How It Works

## Case 1: Left Half is Sorted

If:

```java
nums[left] <= nums[mid]
```

then the left half is sorted.

```text
left              mid
 ↓                  ↓
[4, 5, 6, 7, 0, 1, 2]
 └────────┘
  sorted
```

Now check whether the target lies within this sorted range:

```java
nums[left] <= target && target < nums[mid]
```

### If yes

Search the left half:

```java
right = mid - 1;
```

### Otherwise

The target must be in the right half:

```java
left = mid + 1;
```

---

## Case 2: Right Half is Sorted

Otherwise, the right half must be sorted.

```text
                 mid              right
                  ↓                 ↓
[4, 5, 6, 7, 0, 1, 2]
             └──────────────┘
                  sorted
```

Check whether:

```java
nums[mid] < target && target <= nums[right]
```

### If yes

Search the right half:

```java
left = mid + 1;
```

### Otherwise

Search the left half:

```java
right = mid - 1;
```

---

# 🔍 Why Does This Work?

Consider:

```text
[4, 5, 6, 7, 0, 1, 2]
```

The array is not completely sorted.

But if:

```text
left = 0
mid = 3
right = 6
```

we have:

```text
[4, 5, 6, 7, 0, 1, 2]
 ↑        ↑        ↑
left     mid     right
```

The left half:

```text
[4, 5, 6, 7]
```

is sorted.

Therefore, we can determine exactly whether the target can exist inside this half.

If the target lies inside the sorted range:

```text
Search left
```

Otherwise:

```text
Discard left
Search right
```

Therefore, we can still eliminate approximately **half of the search space** at every iteration.

This gives:

```text
O(log n)
```

just like normal Binary Search.

False.


Check sorted half:

```text
0 <= 1
```

So the left half is sorted.

Check whether target lies there:


True.

# 🔄 Approach: Modified Binary Search

```java
class Solution {

    public int search(int[] nums, int target) {

        int n = nums.length;
        int left = 0;
        int right = n - 1;

        while(left <= right){

            int mid = left + (right - left) / 2;

            if(nums[mid] == target)
                return mid;

            // Left side is sorted
            if(nums[left] <= nums[mid]){

                // Check whether target lies in left space
                if(target >= nums[left] && target < nums[mid]){
                    right = mid - 1;
                }
                else{
                    // Target is not in left space
                    left = mid + 1;
                }

            }
            else{

                // Right side is sorted

                // Check whether target lies in right space
                if(target > nums[mid] && target <= nums[right]){
                    left = mid + 1;
                }
                else{
                    // Target is in left space
                    right = mid - 1;
                }
            }
        }

        return -1;
    }
}
```

# 📊 Complexity

| Complexity | Value      |
| ---------- | ---------- |
| Time       | `O(log n)` |
| Space      | `O(1)`     |

At every iteration, approximately half of the search space is eliminated.

---

# 🎯 Key Takeaways

* A rotated sorted array is **not completely sorted**.
* However, **at least one half is always sorted**.
* Identify the sorted half using:

```java
nums[left] <= nums[mid]
```

* Check whether the target lies inside that sorted half.
* If it does, search that half.
* Otherwise, search the other half.
* This allows us to maintain:

```text
Time = O(log n)
Space = O(1)
```

### ⭐ Pattern

```text
Find sorted half
       ↓
Check if target belongs there
       ↓
Yes → Search sorted half
       ↓
No  → Search other half
       ↓
Repeat
```

This is a classic example of **Modified Binary Search**.
