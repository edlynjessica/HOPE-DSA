# 377. Combination Sum IV

## 📖 Problem Statement

Given an array of **distinct integers** `nums` and an integer `target`, return the **number of possible combinations** that add up to the target.

Unlike **Coin Change**, **different orders are counted as different combinations.**

For example,

```text
1 + 2 + 1
```

and

```text
2 + 1 + 1
```

are considered **different**.

---

# 💡 Observation

At every target value,

we try every number in the array as the **last chosen number**.

If we choose a number `num`,

then the remaining target becomes

```text
target - num
```

The number of ways to form the current target is therefore the sum of the ways to form all valid remaining targets.

Since the same targets are computed repeatedly, Dynamic Programming is used.

---

# 🧠 DP Thinking

## What does the question ask?

Find the **number of ordered combinations** that sum to the given target.

---

## What is the subproblem?

Let

```text
dp[i]
```

represent the **number of ways to form the sum `i`.**

---

## Recurrence Relation

Try every number in the array.

If

```text
num <= i
```

then

```text
dp[i] += dp[i - num]
```

---

## Base Case

```text
dp[0] = 1
```

There is exactly **one way** to make a sum of `0`:

choose nothing.

This serves as the starting point for building larger sums.

---

# ✅ Approach : Tabulation (Bottom-Up DP)

### Idea

Build the DP array from

```text
0 → target
```

For every target value,

try using every number in the array.

Accumulate all possible ways.

---

### Time Complexity

```text
O(target × nums.length)
```

---

### Space Complexity

```text
O(target)
```

---

### Code

```java
class Solution {
    public int combinationSum4(int[] nums, int target) {

        // tabulation approach

        int[] dp = new int[target + 1];

        dp[0] = 1; // base case

        for(int i = 1; i <= target; i++){

            for(int num : nums){

                if(num <= i)
                    dp[i] += dp[i - num];
            }
        }

        return dp[target];
    }
}
```

---

# 📊 Complexity

| Approach | Time Complexity | Space Complexity |
|-----------|-----------------|------------------|
| Tabulation | O(target × nums.length) | O(target) |

---

# 🔄 Difference from Coin Change

Although both problems look similar, the DP transition is different.

### Coin Change (Minimum Coins)

Goal:

```text
Find the minimum number of coins.
```

Transition:

```text
dp[i] = min(dp[i], dp[i - coin] + 1)
```

Order does **not** matter.

---

### Combination Sum IV

Goal:

```text
Count the number of ordered combinations.
```

Transition:

```text
dp[i] += dp[i - num]
```

Order **does** matter.

For example,

```text
1 + 2

≠

2 + 1
```

Both are counted separately.

---

# 🎯 Key Takeaways

- Combination Sum IV is a classic **Counting DP** problem.
- Define the DP state as:

```text
dp[i]
```

= Number of ordered ways to form the sum `i`.

- Base case:

```text
dp[0] = 1
```

- For every target value, try every number.
- Since **order matters**, iterate over the **target first**, then the numbers.
- The recurrence is:

```text
dp[i] += dp[i - num]
```
